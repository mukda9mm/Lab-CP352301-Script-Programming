## 1. เป้าหมาย

พัฒนา Task Manager จาก Class Activity 1 (procedural), Class Activity 2 (OOP) และ Class Activity 4 (ออกแบบโครงสร้าง) ให้เป็นโปรแกรม CLI ที่ใช้งานได้จริง สำหรับติดตามงานในรายวิชา เช่น กำหนดส่งแลป วันสอบ และงานที่ยังค้าง

## 2. ความต้องการของระบบ (Requirements)

| ฟีเจอร์ | รายละเอียด |
| --- | --- |
| ประเภทงาน 3 แบบ | `Task` งานทั่วไป, `DueDateTask` งานที่มีวันครบกำหนด, `PriorityTask` งานที่มีระดับความสำคัญ High / Medium / Low |
| Tags | แต่ละงานมีได้หลาย tag ระบบแปลงเป็นตัวพิมพ์เล็กและป้องกัน tag ซ้ำ |
| CRUD | เพิ่ม แสดงทั้งหมด ทำเครื่องหมายว่าเสร็จ และลบงาน |
| Search | ค้นหาคำบางส่วนใน description และ tags โดยไม่สนตัวพิมพ์เล็ก-ใหญ่ |
| Filter | กรองหลายเงื่อนไขพร้อมกัน ได้แก่ สถานะ ช่วงวันครบกำหนด ระดับความสำคัญ และ tags |
| Sort | เรียงตาม ID, ชื่องาน, สถานะ, วันครบกำหนด และระดับความสำคัญ ทั้งน้อยไปมากและมากไปน้อย |
| Persistence | บันทึกลง `data/tasks.json` และโหลดกลับเป็น object ตามประเภทเดิมจากฟิลด์ `_type` |

## 3. สถาปัตยกรรม (Architecture)

```
Task ──┬── DueDateTask   (+ due_date)
       └── PriorityTask  (+ priority)
```

| โมดูล | หน้าที่ |
| --- | --- |
| `src/task.py` | Domain model: คลาส `Task` และคลาสลูก |
| `src/data_persistence.py` | อ่าน/เขียนไฟล์ JSON และแปลงข้อมูลกลับเป็น object |
| `src/task_manager.py` | Business logic: เพิ่ม ลบ ค้นหา กรอง และเรียงลำดับ |
| `src/cli_interface.py` | Presentation layer: เมนูและการรับข้อมูลจากผู้ใช้ |
| `main.py` | จุดเริ่มต้นโปรแกรม |

การแยกชั้นตามหลัก Separation of Concerns ทำให้แต่ละส่วนเปลี่ยนได้อิสระ เช่น หากต้องการเปลี่ยนจาก CLI เป็นหน้าเว็บ จะแก้เฉพาะชั้น presentation โดยใช้ `task_manager.py` และ `data_persistence.py` ต่อได้ทันที

## 5. ปัญหาทางเทคนิคและแนวทางแก้ไข (Technical Challenges)

**5.1 การกรองตามวันครบกำหนดเมื่องานบางประเภทไม่มีวันครบกำหนด**
`Task` และ `PriorityTask` ไม่มี attribute `due_date` การเปรียบเทียบโดยตรงจึงเกิด `AttributeError` แนวทางแก้คือตรวจด้วย `isinstance(t, DueDateTask)` ก่อนเปรียบเทียบ และแปลงข้อมูลนำเข้าเป็น `datetime.date` แทนการเปรียบเทียบเป็นข้อความ

**5.2 การเรียงลำดับข้อมูลหลายประเภทในรายการเดียว (Polymorphic Sort)**
- เรียงตามวันครบกำหนด: ใช้ key เป็น `datetime.date.max` สำหรับงานที่ไม่มีวันครบกำหนด งานเหล่านั้นจึงอยู่ท้ายรายการโดยอัตโนมัติ
- เรียงตามความสำคัญ: ค่า `High`, `Medium`, `Low` เป็นข้อความ หากเรียงตรง ๆ จะได้ลำดับตามตัวอักษร (High, Low, Medium) ซึ่งไม่ถูกต้อง จึงใช้ `PRIORITY_MAP = {"High": 1, "Medium": 2, "Low": 3}` และกำหนดค่า 99 ให้งานที่ไม่มีระดับความสำคัญ

**5.3 ความต่างระหว่างการค้นหาและการกรองด้วย tags**
การค้นหาใช้ `any(...)` เพราะต้องการงานที่ตรงกับ tag ใดก็ได้ ส่วนการกรองใช้ `all(...)` เพราะต้องการงานที่มี tag ครบทุกตัวที่ระบุ

**5.4 Tag ซ้ำที่ต่างกันเพียงตัวพิมพ์หรือช่องว่าง**
ข้อมูล `Study`, ` study ` และ `STUDY` ควรเป็น tag เดียวกัน จึงปรับค่าใน `add_tag()` ด้วย `strip().lower()` และตรวจสอบก่อนเพิ่มว่ามีอยู่แล้วหรือไม่

**5.5 การโหลดข้อมูลกลับให้เป็น object ประเภทเดิม**
JSON เก็บได้เพียง dict หากไม่ระบุประเภท ข้อมูลจะถูกโหลดกลับเป็น `Task` ทั้งหมด จึงเพิ่มฟิลด์ `_type` ใน `to_dict()` และให้ `load_tasks()` อ่านฟิลด์นี้เพื่อสร้าง `DueDateTask` หรือ `PriorityTask` ให้ถูกต้อง พร้อมใช้ `setdefault('tags', [])` เพื่อรองรับไฟล์ข้อมูลรุ่นเก่าที่ยังไม่มี tags

## 6. สิ่งที่ได้เรียนรู้ระหว่างพัฒนาและจัดการ repository

**6.1 การย้ายโฟลเดอร์ที่ถูกโปรแกรมอื่นใช้งานอยู่**
ตอนจัด repository ใหม่เป็นหมวดตาม Classroom คำสั่ง `Move-Item` ย้ายโฟลเดอร์แลป ADV1 ไม่ได้และขึ้น `Access ... is denied` สาเหตุคือ `chromedriver` ที่ Selenium เปิดค้างไว้ยังถือไฟล์ในโฟลเดอร์นั้นอยู่ เมื่อปิด process ดังกล่าวแล้วจึงย้ายได้ และใช้ `git add -A` ให้ Git ตรวจจับเป็นการเปลี่ยนชื่อ (renamed) แทนการลบแล้วสร้างใหม่

**6.2 การแก้ไขไฟล์บนเว็บ GitHub แล้ว push ไม่ผ่าน**
หลังแก้ README ผ่านหน้าเว็บ GitHub การ `git push` จากเครื่องถูกปฏิเสธ (`rejected ... fetch first`) เพราะ remote มี commit ที่เครื่องยังไม่มี แก้ด้วย `git pull --rebase` และเปลี่ยนวิธีทำงานเป็นสั่ง `git pull` ก่อนเริ่มงานทุกครั้ง

**6.3 การเข้ารหัสอักขระและเครื่องมือแก้ไขข้อความ**
README หลักเคยเสียหายเพราะโปรแกรมแก้ไขข้อความแปลงเนื้อหา Markdown ตอนวาง (เติม `#` ทุกบรรทัดและใส่ `\` หน้าสัญลักษณ์) จึงเปลี่ยนมาเขียนไฟล์ด้วยการเข้ารหัส UTF-8 โดยตรง และตรวจผลด้วย `Get-Content -Encoding UTF8` ก่อน commit

**6.4 การป้องกันข้อมูลลับ**
แลปอีเมลต้องใช้ Gmail App Password จึงเก็บค่าไว้ในไฟล์ `.env` ที่อยู่ใน `.gitignore` และตรวจ `git status` ทุกครั้งก่อน commit ว่าไม่มี `.env` หรือโฟลเดอร์ `venv` ติดขึ้นไป
